# v2.2 Feedback + Scope

**Captured:** 2026-05-02
**Status:** Plan only (not yet built)
**Origin:** User asked for a "historic moments" content type — written stories with optional audio narration. Examples: starting the martial arts school, starting the family business, a family member's motorcycle accident.

---

## Naming decision

**Section name: Chronicles.**

Rejected alternatives (kept for record):
- *Stories* — too generic; every site has stories
- *Histories* — too dry; reads like a textbook section
- *Beginnings* — too narrow; doesn't fit later watershed events
- *The Record* — too museum-stuffy
- *The Telling* — too clever; cognitive overhead for new visitors

Why Chronicles works: literally means "an account or recording of historical events," carries the right archival weight for the AgeWish tone, sits well alongside Photographs/Videos as a noun of substance, accommodates both founding moments AND personal stories, reads beautifully as a Cormorant Garamond serif heading.

## Phase 19 scope (single phase, two plans)

### Data model

`content/chronicles.json` — array of:

```jsonc
{
  "id": "starting-the-martial-arts-school",   // kebab-case slug
  "title": "Starting the Curry Martial Arts School",
  "subtitle": "How a basement studio became a 30-year institution",  // optional eyebrow phrase
  "body": "In the summer of 1979, Robert Curry...",  // markdown source
  "audioFilename": "starting-the-school-narration.mp3",  // optional, file in /public/audio/
  "audioDuration": "8:42",
  "date": "1979-06-01",                       // ISO YYYY-MM-DD, optional
  "dateLabel": "Summer 1979",                 // display, optional
  "peopleIds": ["robert-curry", "william-curry"],   // who's in this story
  "coverPhotoId": "1979-school-opening-01",   // optional, displayed at top of detail page
  "collectionIds": [],                        // chronicles CAN tag into collections (future-proof)
  // Provenance (Phase 15 pattern)
  "source": "...",
  "identifiedBy": "...",
  "confidence": "high",
  "lastVerified": "2024-08-15"
}
```

**Audio is embedded directly on the chronicle**, not referenced from `audio.json`. Reason: a chronicle's audio is the chronicle being read aloud — they're 1:1, not many-to-many. Standalone audio (voicemails, songs, oral history snippets without a written counterpart) continues to live in `audio.json`.

### Body format

**Markdown** (per user choice). Adds `react-markdown` dependency. Author can use italics for emphasis, blockquotes for direct quotes from a relative, em-dashes, the occasional bold. Plain text still renders fine — markdown is permissive about no formatting. Renders to clean serif prose using Cormorant Garamond.

### Routes

| Route | Purpose |
|-------|---------|
| `/chronicles` | Landing page — list of chronicle cards (cover photo + title + subtitle + dateLabel + duration + first ~150 words preview) |
| `/chronicles/[id]` | Individual chronicle — hero (cover photo if present), title, subtitle, dateLabel, AudioPlayer at top so the narration is findable, then markdown-rendered body, then "About the people in this story" linking to person pages |

### Component additions

- `components/chronicles/ChronicleCard.tsx` — list view card (Server Component)
- `components/chronicles/ChronicleGrid.tsx` — grid of cards (Server Component)
- `components/chronicles/ChronicleBody.tsx` — markdown renderer ('use client' only if `react-markdown` requires it; otherwise Server)
- Reuse existing `<AudioPlayer />` for the narration — passes the chronicle's `audioFilename` + `audioDuration` + a derived title field

### Cross-cutting integrations

1. **TopNav** — add 5th tab "Chronicles" between Videos and Sign out (if Sign out still existed; it doesn't). New order: Home / Family tree / Photographs / Videos / Chronicles. NavTabs already has `overflow-x-auto` on mobile, so 5 tabs scroll if they don't fit.

2. **Person page** — add section "CHRONICLES FEATURING {NAME}" listing chronicles where person appears in `peopleIds[]`. Each entry links to `/chronicles/[id]`.

3. **Home page** — add a "Recent chronicles" preview section (1-2 latest by date). Each preview links to its chronicle.

4. **Collection detail page** — Phase 8 currently shows photos only. Future: also show chronicles tagged to that collection. Out of scope for Phase 19; data model supports it via `collectionIds[]`.

5. **Bidirectional validator** in `lib/content.ts` — extend to validate every `Chronicle.peopleIds[]` resolves; every `Chronicle.coverPhotoId` resolves; every `Chronicle.collectionIds[]` resolves.

6. **Archive export** (Phase 18) — extend `manifest.zip` to include `chronicles.json` and the static `index.html` template to include a Chronicles tab.

7. **Deep linking** (Phase 16 pattern) — `/chronicles/[id]?audio=playing` could mark playback state in the URL. Stretch goal; not required for v1.

## Items deliberately deferred

- Chronicle search/filtering (out of scope; index page chronological is enough)
- Chapter divisions within a chronicle (markdown headers handle this naturally; no special UI needed)
- Author attribution per chronicle (could add `writtenBy` and `narratedBy` fields if useful — currently provenance covers this generically via `identifiedBy`)
- Chronicle cross-references (chronicles linking to other chronicles) — markdown links already work; no special schema needed
- Print stylesheet for chronicles — would be lovely but Phase 19 ships without it; can be added in a future polish pass
