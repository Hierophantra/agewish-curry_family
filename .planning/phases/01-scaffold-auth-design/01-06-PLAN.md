```markdown
# The Curry Family Hub

A private family archive for the Curry family at [curry.agewish.com](https://curry.agewish.com).

## Local development

**Prerequisites:** Node.js 18+, npm

```bash
# Clone and install
git clone <repo-url>
cd curry-family
npm install

# Set up environment variables
cp .env.local.example .env.local
# Edit .env.local — see "Environment variables" section below

# Run the development server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) and log in with the family password.

## Environment variables

Copy `.env.local.example` to `.env.local` and fill in both values.

### Generate AUTH_SECRET

```bash
npx auth secret
# Copy the output to AUTH_SECRET in .env.local
```

### Generate AUTH_PASSWORD_HASH

```bash
node -e "require('bcryptjs').hash('<your-family-password>', 10).then(console.log)"
# Replace <your-family-password> with the actual family password
# Copy the $2a$10$... output to AUTH_PASSWORD_HASH in .env.local
# NEVER store the plaintext password — only the hash
```

## Content authoring

All family content lives in the `content/` folder. Update these files and push to publish.

**`content/family.json`** — Family members
- Add each person as a JSON object with `id` (kebab-case slug), `name`, `birthYear`, `photoIds`, etc.
- Person `id` is stable forever — do not rename after publishing (used in URLs and cross-references)
- Example: `"id": "william-curry"` → accessible at `/person/william-curry`

**`content/photos.json`** — Family photographs
- `filename` refers to a file in `/public/photos/`
- `peopleIds` links the photo to people in `family.json` (bidirectional — also add `photoIds` on the person)

**`content/videos.json`** — Family films
- `source`: `"youtube"` or `"vimeo"`
- `sourceId`: the YouTube/Vimeo video ID (not the full URL)

**Publishing:** Commit the updated JSON files and push. Vercel rebuilds automatically.

## Vercel deployment

### First deploy

1. Push the repo to GitHub
2. Import the project in [Vercel dashboard](https://vercel.com)
3. Add environment variables (Settings → Environment Variables):
   - `AUTH_SECRET` — check **Production**, **Preview**, **Development**
   - `AUTH_PASSWORD_HASH` — check **Production**, **Preview**, **Development**
4. Do NOT set `NEXTAUTH_URL`, `AUTH_URL`, or `NEXTAUTH_SECRET` — these break preview deployments

### DNS (curry.agewish.com)

1. In Vercel: Project Settings → Domains → Add `curry.agewish.com`
2. Vercel shows a CNAME record value (project-specific)
3. In your DNS registrar: add a CNAME record `curry` → `<Vercel CNAME value>`
4. SSL certificate auto-provisions once DNS propagates (5-30 minutes)

### Password rotation

To change the family password:
1. Generate a new hash: `node -e "require('bcryptjs').hash('<new-password>', 10).then(console.log)"`
2. Update `AUTH_PASSWORD_HASH` in Vercel environment variables
3. Redeploy (existing sessions remain valid — they used the old password to create a JWT, not the hash)

To invalidate ALL sessions (nuclear option — everyone must log in again):
1. Generate a new `AUTH_SECRET`: `npx auth secret`
2. Update `AUTH_SECRET` in Vercel environment variables
3. Redeploy

## Tech stack

- **Next.js 14.2.35** — App Router (do not upgrade to 15/16)
- **Auth.js v5 (next-auth@beta)** — Credentials provider, JWT sessions
- **Tailwind CSS v4** — CSS-first config in `app/globals.css`
- **Zod** — JSON content validation
- **bcryptjs** — Password hash comparison

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer → .env.local | Real secrets created here; never committed |
| .env.local → Vercel env vars | Secrets transmitted to Vercel dashboard over HTTPS |
| README.md → git repo | README is committed — must not contain any real secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-06-01 | Information Disclosure | README.md | mitigate | README documents hash generation process but never contains a real hash value; .env.local is in .gitignore |
| T-06-02 | Information Disclosure | Vercel env vars | accept | AUTH_SECRET and AUTH_PASSWORD_HASH are set via Vercel dashboard HTTPS; Vercel encrypts env vars at rest |
