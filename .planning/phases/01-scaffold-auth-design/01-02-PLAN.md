**auth.config.ts — EDGE-SAFE. CRITICAL RULES:**
- NO `import bcryptjs` — bcryptjs has Node.js APIs that crash the edge runtime
- NO `import { readFileSync } from 'fs'` — fs is not available in edge runtime
- NO `import path from 'path'` — path is not available in edge runtime
- Only allowed imports: `next-auth`, `next-auth/providers/*`

```typescript
// auth.config.ts
// EDGE-SAFE — imported by middleware.ts which runs in the Edge Runtime.
// Do NOT add bcryptjs, fs, path, crypto, or any Node.js-only imports here.
import type { NextAuthConfig } from 'next-auth'
import Credentials from 'next-auth/providers/credentials'

export default {
  providers: [
    Credentials({
      credentials: {
        password: { label: 'Password', type: 'password' },
      },
      // authorize() here is a stub — the real bcryptjs check is in auth.ts.
      // auth.ts overrides this provider with the full version.
      // Returning null from here means "not authorized" — auth.ts replaces this behavior.
      async authorize() {
        return null
      },
    }),
  ],
  pages: {
    signIn: '/login',
  },
  callbacks: {
    // Controls whether middleware allows the request or redirects to /login.
    // Called on every request matched by middleware.ts matcher.
    // Does NOT re-run authorize() — that only runs on sign-in form submission.
    authorized({ auth }) {
      return !!auth?.user
    },
  },
} satisfies NextAuthConfig
```

**auth.ts — NODE.JS ONLY. Never imported by middleware.ts.**

The `providers` array in auth.ts OVERRIDES the stub provider from authConfig spread.
The spread (`...authConfig`) must come BEFORE `providers:` key, otherwise spread overwrites our full provider.

```typescript
// auth.ts
// NODE.JS ONLY — imports bcryptjs. NEVER import this file from middleware.ts.
// If middleware.ts imports from here, bcryptjs enters the edge runtime and build fails.
import NextAuth from 'next-auth'
import Credentials from 'next-auth/providers/credentials'
import bcrypt from 'bcryptjs'
import authConfig from './auth.config'

export const { auth, handlers, signIn, signOut } = NextAuth({
  ...authConfig, // Spreads pages, callbacks from auth.config.ts
  providers: [
    // This provider REPLACES the stub in auth.config.ts
    Credentials({
      credentials: {
        password: { label: 'Password', type: 'password' },
      },
      async authorize(credentials) {
        const password = credentials?.password
        if (typeof password !== 'string' || password.length === 0) return null

        const hash = process.env.AUTH_PASSWORD_HASH
        if (!hash) {
          // Fail loudly — missing env var means no one can log in
          throw new Error('AUTH_PASSWORD_HASH env var is not set')
        }

        const isValid = await bcrypt.compare(password, hash)
        if (!isValid) return null

        // Single shared identity for the whole family
        return { id: 'family', name: 'Family Member' }
      },
    }),
  ],
  session: {
    strategy: 'jwt',
    maxAge: 30 * 24 * 60 * 60, // 30 days in seconds
  },
})
```

**middleware.ts — imports ONLY from auth.config.ts:**

```typescript
// middleware.ts
// CRITICAL: Import from './auth.config' ONLY.
// If you change this to import from './auth', bcryptjs enters the edge runtime
// and the build will fail with: "Module 'crypto' cannot be resolved in edge runtime"
import NextAuth from 'next-auth'
import authConfig from './auth.config'

const { auth } = NextAuth(authConfig)

export default auth

export const config = {
  // Run middleware on all routes EXCEPT:
  // - /api/* — Auth.js route handlers
  // - /_next/static — static file serving
  // - /_next/image — image optimization
  // - /favicon.ico — browser favicon request
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
}
```

The `authorized` callback in `auth.config.ts` determines whether middleware allows or redirects.
When `authorized` returns false → redirect to `pages.signIn` (`/login`).
When `authorized` returns true → `NextResponse.next()` (allow request).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → middleware (edge) | JWT cookie read at edge; redirects unauthenticated requests |
| Browser → /api/auth/* (Node.js) | Password submission via form POST; bcrypt comparison here |
| auth.config.ts → edge runtime | Any Node.js-only import here crashes the build |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | middleware.ts (CVE-2025-29927) | mitigate | Middleware is fast-path UX only; every protected Server Component calls `await auth()` independently (implemented in Plan 04) |
| T-02-02 | Spoofing | auth.ts authorize() | mitigate | bcrypt.compare() with AUTH_PASSWORD_HASH; no plaintext password comparison; bcrypt cost factor 10 |
| T-02-03 | Tampering | JWT session cookie | mitigate | AUTH_SECRET used for HMAC-SHA256 signing via Auth.js; never hand-rolled |
| T-02-04 | Information Disclosure | auth.ts authorize() | mitigate | Error messages never leak plaintext password or hash; "Family Member" identity returned (no PII) |
| T-02-05 | Information Disclosure | .env.local | accept | .gitignore excludes .env.local; .env.local.example committed with empty values only |
| T-02-06 | Elevation of Privilege | auth.config.ts edge import | mitigate | auth.config.ts imports enforced via acceptance criteria grep check; bcryptjs/fs imports are build-time failures |
| T-02-07 | Tampering | Stale JWT after password change | accept | Changing AUTH_PASSWORD_HASH does not invalidate existing JWTs; changing AUTH_SECRET invalidates all sessions (documented in README — Plan 06) |
</threat_model>
