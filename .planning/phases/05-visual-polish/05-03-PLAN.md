PersonPanel positioning detail: The PersonPanel is rendered as an absolute child of
FamilyTreeCanvas's inner relative div. On mobile, absolute positioning inside a
small-height container means the panel appears mid-page, partially off-screen.

not absolute inside the tree container. On md+, keep the current absolute behavior.

`inset-x-0 md:inset-x-auto md:right-0`, `h-auto md:h-full`, `max-h-[60vh] md:max-h-none`.

  <action>
    **FamilyTreeCanvas.tsx — right-edge gradient indicator (per D-12):**

    The outer wrapper div already has `overflow-x-auto`. Add a relative wrapper around it
    to host the pseudo-element gradient. In Tailwind v4, CSS custom utilities via `@utility`
    are in globals.css. However, since the gradient is a one-off, use an inline approach:
    wrap the existing `overflow-x-auto` div in a new `relative` div, and add an absolutely
    positioned gradient overlay div inside it:

    ```tsx
    <div className="relative">
      {/* Fade indicator — signals more content to scroll on mobile */}
      {/* Hidden on large screens (lg:hidden) where tree typically fits */}
      <div
        className="pointer-events-none absolute right-0 top-0 h-full w-12 z-20 lg:hidden"
        style={{
          background: 'linear-gradient(to right, transparent, white)',
        }}
        aria-hidden="true"
      />
      <div className="overflow-x-auto">
        {/* existing relative canvas div and all children — unchanged */}
      </div>
    </div>
    ```

    The gradient uses `white` (the page background) as the fade target. On the /tree page
    the canvas background is white. The `pointer-events-none` ensures the gradient div
    does not block scroll touch events. `lg:hidden` hides it on laptop+ where the tree fits.

    Do NOT change any logic inside the existing `overflow-x-auto` div — only wrap it.

    **PersonPanel.tsx — mobile bottom-sheet (per D-16):**

    Change the `motion.aside` className to use responsive classes:

    Current:
    ```tsx
    className="absolute top-0 right-0 h-full w-80 bg-ivory border-l hairline z-10 flex flex-col overflow-y-auto"
    ```

    Replace with:
    ```tsx
    className="fixed bottom-0 inset-x-0 max-h-[60vh] rounded-t-xl md:absolute md:top-0 md:right-0 md:bottom-auto md:inset-x-auto md:h-full md:w-80 md:rounded-none bg-ivory border-t hairline md:border-t-0 md:border-l z-10 flex flex-col overflow-y-auto"
    ```

    This gives:
    - Mobile (< md): fixed bottom-sheet, full width, max 60% viewport height, rounded top corners
    - Tablet/desktop (md+): absolute right panel, full height, 320px wide (original behavior)

    The border changes: mobile has `border-t` (top edge of sheet), desktop has `border-l` (left edge of panel).
    `md:border-t-0` removes the top border on desktop; `md:border-l` adds the left border.

    Update the motion initial/exit values to be responsive too. Since we cannot use
    Tailwind classes on motion `initial`/`animate`, keep the existing slide-from-right
    animation (`initial={{ x: '100%', opacity: 0 }}`). On mobile this means the sheet
    slides from the right edge off-screen — acceptable; the panel still feels deliberate.
    If desired by the developer, the animation can be tuned after visual QA.

    After both changes, confirm the build passes: `npm run build`.

    **NavTabs.tsx — horizontal scroll on mobile (per D-15):**

    Current outer div: `className="flex items-center gap-6"`

    Replace with:
    ```tsx
    <div className="overflow-x-auto scrollbar-none flex items-center gap-6 -mx-2 px-2">
    ```

    `overflow-x-auto` allows horizontal scroll when tabs overflow the container.
    `-mx-2 px-2` adds slight horizontal breathing room so the active tab underline
    is not clipped at the container edge when scrolled.
    `scrollbar-none` hides the scrollbar on Webkit (Chrome/Safari/mobile) for a cleaner
    look — Tailwind v4 generates this utility from the standard variant.
